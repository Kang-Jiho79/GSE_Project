- `[ ]`로 남은 값은 임의로 정하지 말고 사용자에게 물어본다.

## 2. 스토리·엔딩 구조의 변경 요약

### 2.1 이명 체계 (확정)
| 시점 | 이명 변화 |
|---|---|
| 시작부터 | **신에게 선택받은 자** (스테이터스 창에 처음부터 표시) |
| 루키우스에게 인정받음 | **가장 어두운 빛** 추가 |
| 녹티스에게 인정받음 | **가장 밝은 어둠** 추가 |
| 신의 영향에서 벗어남 | "신에게 선택받은 자"가 **판을 벗어난 자**로 교체 |

- 기존의 "6단계 인정 시 이명 '가장 어두운 빛이자 가장 밝은 어둠' 획득"은 폐기. 인정 시 **축복 + 각 왕의 이명 하나씩** 얻는다.
- 기존의 "8단계에서 이명 '신에게 선택받은 자' 획득"도 폐기. 그 사건은 **이명의 교체**가 된다 (영향에서 벗어난 것과 선택받는 것은 반대이기 때문).
- 시작 이명은 플레이어에게 멋진 칭호로 보이지만, 출생의 비밀(신이 보낸 존재)을 미리 보여 주는 복선이다.
- **이명 효과 (결정)**: **판을 벗어난 자**만 효과가 있다 — **침식 허용치 제한 해제** (불균형이 아무리 커져도 잿빛 침식이 일어나지 않음). 나머지 이명은 효과 없이 표시만 한다 (능력 보정은 왕의 축복이 담당).

### 2.2 신의 개입은 두 번 (확정)
1. **첫 번째 (7단계)**: 인정한 왕에게 결탁을 물으면 왕이 오류 반응 → 신이 개입해 대화를 막고 주인공을 벨룸 평원으로 보낸다 (4번 항목).
2. **두 번째 (8단계 이후)**: 영향에서 벗어난 주인공이 왕과 왕비를 다시 찾아가면, 신이 개입해 두 사람을 **킹과 퀸으로 변모**시킨다 (11번 항목). 신의 개입이 점점 강해지는 흐름.

### 2.3 진엔딩 조건과 경로 (변경)
- 진엔딩 조건 B: "신에게 선택받은 자 이명 획득" → **"신의 영향에서 벗어남(이명이 '판을 벗어난 자'로 교체됨)"** 으로 변경
- **영향 이탈 조건 (결정)**: 지금 구현 그대로 유지 — 두 왕 추궁(신의 개입을 두 번 겪음) + 구원 두 번 + 엿듣기 + 빛·어둠 누적치 합 400 이상 (`Tuning::Story::kChosenPower`)
  - 4번에 따라 추궁은 인정한 왕에게만 할 수 있으므로, B를 갖추면 A도 갖춘 셈이 된다.
- 진엔딩 경로에 **킹·퀸 보스전(필수)** 추가. 진엔딩 조건 미충족자는 이 단계를 겪지 않는다.
- 진엔딩 조건: A(두 왕의 인정) + B(영향 이탈) + **두 나라의 킹·퀸 모두 격파** → 이후 키니스 → 마지막 선택 → 신
- **A·B는 갖췄지만 킹·퀸을 다 깨지 않은 경우 (결정)**: **체크메이트 엔딩** (2.4 표, 11번 항목)
- 플래그 이름은 기존 이름 유지 원칙에 따라 판단하되, 의미가 바뀌는 `titleChosenByGod`는 이름과 의미가 어긋나지 않게 정리한다.
  - 기본안: `TitleChosenByGod`를 지우고 `EscapedGodInfluence` 하나로 합침 (새 체계에서 두 플래그의 뜻이 같아짐). 이전 저장 파일의 이 이름은 불러올 때 무시. 킹·퀸 격파는 나라별 플래그를 새로 둠

### 2.4 잿빛과 신 (확정)
- **빛과 어둠은 신이 만든 힘** (쓰러뜨린 이의 힘을 흡수하는 능력도 신이 준 것)이고, **잿빛은 신의 예상 밖에서 생긴, 신의 규칙이 닿지 않는 유일한 힘**이다.
- 따라서 **신은 잿빛을 쓰지 않는다.** 신의 공격은 빛·어둠·두 힘을 합친 **흰색**이다.
- 잿빛을 받아들이면 **빛과 어둠의 힘을 모두 잃고 잿빛만 쓴다.** 신의 힘을 버려야 신을 이긴다는 대가 구조 (6번 항목).
  - **(결정)** 잿빛폼은 수락한 뒤에만 쓴다. 빛·어둠·잿빛 세 폼을 함께 쓰는 시점은 없다 → 보스 기믹은 빛·어둠 두 폼 기준 (15번)
- 3번 엔딩(잿빛 엔딩)과 5번 엔딩(진엔딩)의 구분: 3번은 신의 영향 아래에서 보스의 제안을 받아 **잿빛에 먹혀 잿빛의 존재가 됨**, 5번은 영향에서 벗어난 상태로 **자기 의지로 잿빛을 쓰는 존재**로 남음.

**엔딩 5종 (결정)**
| 조건 | 선택 | 엔딩 |
|---|---|---|
| 진엔딩 조건 미충족 | 키니스의 제안 거절 → 키니스 처치 | **구원자 엔딩** (1·2번) |
| 진엔딩 조건 미충족 | 키니스의 제안 수락 (보스전 없음) | **잿빛 엔딩** (3번) |
| A·B 충족, 킹·퀸 일부 또는 전부 미격파 | 선택 없음 (유언 뒤 선택 전에 킹·퀸 등장) | **체크메이트 엔딩** (신규) |
| A·B 충족 + 킹·퀸 모두 격파 | 키니스 처치 후 잿빛 거부 | **버려진 말 엔딩** (4번, 옛 "신의 계략 엔딩") |
| A·B 충족 + 킹·퀸 모두 격파 | 키니스 처치 후 잿빛 수락 → 신 처치 | **진엔딩** (5번) |

### 2.5 변경된 스토리 단계 (4.3 갱신용)

### 3. 오픈월드 맵 개편 (계획 먼저)
지금은 지역 21개가 따로 로딩되고 웨이스톤에서 월드맵으로 이동한다. 이를 **걸어서 이어지는 하나의 월드**로 바꾼다.

**목표**: 크기보다 **촘촘함**. 지역은 작게, 연결 구간은 짧게, 빈 공간 없이 볼거리와 적을 채운다.

**배치 (벨룸 평원이 중앙 허브)**
```
                 북: 잿빛 변경 → 마을 4곳 → 디비시오 → 키네라
                                   │
서: 알바→솔라→아우라→빛의 관문→루멘 ─ 벨룸 평원 ─ 움브라→녹스→크립타→어둠의 관문→테네브라에 (동)
                                   │
                         남: 크레푸스 → 리미나 숲 → 리미나
```
- 서쪽·동쪽 팔의 배치 [ ] — 펼치면 팔이 너무 길고, 접어서 두 수도를 북쪽 양옆에 붙이면 전쟁 중인 두 나라의 수도가 붙어 있어 어색함. 검토할 안:
  1. **V자**: 두 팔을 북서·북동 대각선으로 뻗음. 수도끼리는 멀고 팔은 십자보다 짧음
  2. **접되 사이를 막음**: 두 수도를 북쪽 양옆에 두되 그 사이를 잿빛 변경·키네라의 넓은 절벽·안개 지대가 가름. 지도에선 가까워도 서로 갈 수 없고 반드시 벨룸을 거침 (전선 너머로 서로를 노려보는 모양)
  3. **팔 줄이기**: 십자는 유지하고 팔마다 지역 하나씩 합침 (예: 알바+솔라 들판)
- 빛의 땅과 어둠의 땅 사이는 절벽이나 잿빛 안개 벽으로 막고, 벨룸 평원과 잿빛 변경에서만 연결

**원칙**
- 지역 하나를 가로지르는 시간: 달리기 기준 20~30초
- 연결 구간은 짧게, 경계마다 시선을 끄는 지형(다리, 협곡, 문)
- 한 화면 안에 적 무리, 지형지물, 건물 같은 볼거리가 항상 걸리게 함

**유지 / 변경**
- **웨이스톤(빠른 이동)과 월드맵은 유지** (가본 곳으로 돌아가는 편의 기능)
- 신의 영역(공백)은 지금처럼 별도 지역으로 유지
- 수도에서 벨룸으로 돌려보내는 텔레포트는 4번 항목으로 대체
- 보스는 지금처럼 지역 끝의 전투 장소에 둠, 저장·부활은 신전 기준 유지
- 분위기(안개·색)는 지역 경계에서 서서히 섞이게 함 (솔라의 금빛에서 변경의 회색으로)
- **몬스터 재생성 규칙 (결정)**: **신전에서 쉬면** 월드 전체를 다시 채우고, **그 지역을 멀리 벗어났다가 돌아오면** 그 지역만 다시 채움. 시간 경과나 부활로는 다시 채우지 않음. "멀리"의 거리는 계획 때 정함
- 영향 범위(예상): `Regions`, `Scene::EnterRegion`, `WorldGrid`, `WorldMapScreen`, `Settlement`, 저장 구조(`SaveGame`), `Progress`

**주의**: 3·7·8·12번은 모두 지도와 마을 구조에 걸려 있으므로 **한 번의 계획 안에서 같이 설계**한다. 이번 변경 중 가장 큰 구조 변경이므로 반드시 "구현 계획 먼저 → 확인 후 구현".

### 4. 텔레포트를 신의 개입으로 변경
- 결투 승리 후의 **자동 텔레포트는 삭제**한다. 승리하면 왕이 무릎 꿇고 인정, 축복을 받는 것까지만.
- 인정한 왕(또는 왕비 곁의 왕)에게 말을 걸면 선택지: **결탁에 대해 묻는다 / 그만둔다**
  - **묻는다**: 왕이 오류 반응(같은 말 반복, 화냄) → 대사가 끊기고 **제단과 같은 흰 표식**이 뜸 → 화면이 하얗게 번지며 **벨룸 평원으로 이동** → 주인공의 반응은 "…뭐지?" 정도의 짧은 혼잣말
  - **그만둔다**: 대화만 끝나고 이동 없음
- 주인공은 신의 존재를 아직 모른다. **"누가 막았어" 같은 대사 금지** (주인공이 영문을 몰라야 8단계 엿듣기의 충격이 산다). 흰 표식은 **플레이어에게만** 단서이며, 이후 제단·엿듣기·신과의 대면에서 이어진다.
- 흰 표식은 지금 모든 제단 위에 떠 있는 흰 마름모(`SettlementActor::DrawAltar`)를 그대로 이어 쓴다.
- 묻지 않은 플레이어는 이 장면을 보지 못함 → 2번 엔딩("위화감을 느끼지 못함")의 근거
- 영향 범위(예상): `KingActor`, `Dialogue`, `StoryEvents`, 흰 표식·화면 번짐 연출

### 5. 신 리디자인
- 기존의 "빈 구멍과 두 손"은 존재감이 약하고 어색하므로 변경
- **모습**: 얼굴 자리에 제단과 같은 **흰 표식이 천천히 회전**하는, 색 없는 흰 윤곽의 **거대한 인간형**. 크기는 플레이어의 열 배쯤, 상체는 맵 가장자리에서 판을 내려다보고 **두 손만 판 위로** 내려와 공격한다.
- **신의 영역**: 체스판 같은 놀이판으로 구성 (칸 단위 공격 예고가 읽기 쉬워짐)
- **공격**: 두 손 내리찍기, 판을 가로지르는 쓸기, 놀이판(같은 색 칸 일제 공격)은 유지. **잿빛 공격은 제거**하고 3번째 결계의 탄 고리는 **빛·어둠이 섞인 흰 탄 고리**로 바꾼다.
- 모델은 코드 생성 박스 조합 + 흰 표식만 따로 회전 (기존 `GodActor` 수정)
- GDD 3.5, 7.3의 신 서술 갱신

### 6. 잿빛 수락 시 빛·어둠 상실, 신 전투 재설계
- 마지막 선택에서 **잿빛을 받아들이면 빛폼과 어둠폼이 사라지고 잿빛폼 하나만 남는다.**
  - Space 폼 순환, 교대 스킬, 균형 게이지·침식은 해제
  - 잿빛폼 기술은 14번 개편을 따름 (좌클릭 낫 콤보, E 풀어내기, Q 소거)
  - **입력 (결정)**: **우클릭 = 대시 베기** (구르기 대신). **Space = 다른 기술** — 무엇을 둘지는 B단계 계획 때 제안 [ ]
  - **스킬 위력 (결정)**: 빛·어둠 누적치와 **무관한 고정값**. 수치는 신 전투에 맞춰 계획 때 정함 [ ]
  - 신 전투에서는 균형 게이지를 숨기고 잿빛 표시만 남김 [제안]
- **신 전투 재설계 [제안]**: 신이 **빛·어둠·흰 힘의 세 결계**를 차례로 펼치고, 플레이어는 잿빛 **E(풀어내기: 결계와 방벽을 깸)** 로 각 결계의 핵을 깨고, 열린 틈에 본체 피해를 넣는다. 기존 "빛 → 어둠 → 잿빛 순서로 그 힘으로만 피해" 구조는 폐기. 체력 1/3씩 세 페이즈는 유지. (B단계 계획 때 확정)
- GDD 3.5(잿빛은 신이 통제하지 못하는 유일한 힘), 4.4, 5.4, 진엔딩 조건 문구의 "세 힘" 표현 갱신
- 영향 범위(예상): `PlayerStatus`, `AshFormMoves`, `Combat`(위력 계산), `GodActor`, `Hud`, `StoryEvents`

### 7. 마을 추가와 퀘스트 시스템
오픈월드에서 처음 하는 사람이 진행 방향을 잃지 않도록 돕는다. 장비와 상점이 없으므로 퀘스트가 마을에 갈 이유도 만든다.

**마을 추가 (이름은 임시)** — 이름 5곳은 D단계에서 Claude 초안 → 검토 [ ]
| 위치 | 마을 | 역할 |
|---|---|---|
| 크레푸스 | 경계 쉼터 | 첫 퀘스트 게시판, 조작·균형 시스템 안내 |
| 벨룸 평원 | 전초 마을 | **허브 마을**. 메인 퀘스트 안내, 모든 방향의 길잡이 |
| 솔라 들판 | 순례자 마을 | 수도로 가는 중간 거점, 왕의 인정 소문 |
| 녹스 들판 | 순례자 마을 | 위와 같음 |
| 잿빛 변경 | 피난민 촌 | 잿빛 지대에 들어가기 전 마지막 거점 |
- 작은 마을도 **신전(작은 제단)은 필수** (기존 규칙 유지, 제단이 어디서나 같은 모양이라는 복선도 더 자주 보이게 됨)

**퀘스트**
- **메인 퀘스트**: 스토리 단계를 따라가는 안내. 다음 목표만 보여 줌 (예: "벨룸 평원의 전초 마을로 가라" → "솔라 또는 녹스의 수도로 가라" → "잿빛 지대 근처의 마을을 찾아라")
- **서브 퀘스트**: 마을 게시판의 의뢰 (몬스터 소탕, 사람 구하기, 전달, 지역 탐험). 목록은 D단계에서 Claude 초안 → 검토 [ ]
- **안내 표시**: 화면에 현재 목표 한 줄, 월드맵·미니맵의 목표 마커, 퀘스트 로그 창(J 키)
- **엔딩 조건은 숨긴다.** "왕에게 인정받아라"는 권해도 되지만 "왕에게 결탁을 물어라"는 퀘스트로 넣지 않는다 (플레이어의 선택으로 남김). 인정이 엔딩을 바꾼다는 점도 알리지 않는다. 킹·퀸전도 메인 퀘스트로 안내하지 않는다 [ ] (체크메이트 엔딩과의 관계상 안내 여부는 계획 때 확인)
- **서브 퀘스트 보상은 퀘스트마다 다르다**
  | 보상 유형 | 효과 |
  |---|---|
  | 빛 흡수 | 빛 누적치와 그릇 증가 |
  | 어둠 흡수 | 어둠 누적치와 그릇 증가 |
  | 양쪽 균등 흡수 | 두 힘이 같은 양 증가 (균형도 불변) |
  | 이야기·정보 | 지름길, 소문, 다음 마을 안내, 복선 |
  - 쏠림을 풀어 주는 수단으로도 쓰임. **보상 표기 (결정): 공개** — 게시판에서 받기 전에 보상 종류가 보임. 보상 수치 [ ]
- 구현은 기존 스토리 플래그와 대화 표를 재사용해 "상태 + 목표 위치 + 완료 조건(방문, 처치 수, 대화, 보스 처치)"로 단순하게. 데이터는 `Tuning.h`와 대화 표 쪽에 둠 (외부 라이브러리 금지)

### 8. 빛·어둠의 흔적
- 잿빛을 바탕으로 두고 **빛과 어둠의 흔적을 포인트 색으로** 얹는다 (맵이 너무 칙칙한 문제 해결, 지역 구분 강화)
- **흔적 예시**
  | 구분 | 흔적 |
  |---|---|
  | 빛 | 땅 틈의 금빛 균열, 꺼져 가는 등불과 첨탑, 후광만 남은 부서진 석상, 금빛 깃발 조각, 떠오르는 빛 입자 |
  | 어둠 | 땅을 가르는 보랏빛 균열, 먹빛 덩굴과 가시, 보랏빛 잔불, 어둠 결정, 가라앉는 그림자 입자 |
  | 섞임 (전쟁터) | 두 색의 부러진 무기·깃발 잔해, 양쪽 색이 번갈아 깜빡이는 균열 |
- **지역별 농도**: 솔라 = 금빛 많음, 녹스 = 보랏빛 많음, 벨룸 = 반반 + 전쟁터 잔해, 잿빛 변경 = 드묾(마을 근처만 약하게), 키네라 = 거의 없음
- **몬스터 분포와 연동 (확정)**: 금빛 흔적이 많은 곳에는 빛 소속 몬스터가, 보랏빛 흔적이 많은 곳에는 어둠 소속이 더 많이 나온다. 풍경만 보고도 어느 쪽 힘이 오를지 짐작할 수 있어 균형 관리가 풍경 읽기로 이어진다.
- 구현: 기존 발광 도형(`SetGlow`)과 블룸을 활용한 발광 소품·입자 추가, 지역 데이터에 흔적 비율 추가, **발광 소품 개수 상한**으로 성능 보호

### 9. 필드 보스 체스 말 통일
- 필드 보스(기존 "잿빛 변이체")를 **"잿빛에 잠식된 신의 말"인 체스 말**로 통일한다. GDD 3.5·7.3의 변이체 서술을 이에 맞게 갱신.
- **소속**: 흰 말 = 빛, 검은 말 = 어둠. 처치 시 원래 소속의 힘을 대량 흡수 (기존 규칙 유지)
- **잠식 표현**: 말이 회색으로 일그러지고 받침대와 몸에 균열이 번짐. 초반에는 정체를 모르고, 후반에 신의 놀이판을 알고 나서 복선이 풀린다.
- **온전한 신의 말**(3장 관문의 룩·나이트)은 지금처럼 유지, 빛·어둠이 똑같이 오르는 복선도 유지. 잠식된 말(소속 흡수)과 온전한 말(균등 흡수)의 차이가 의문을 더 키운다.
- **보스 배치와 패턴 (초안)** — 상세 패턴은 C단계 계획 때 [ ]
  | 보스 | 위치 | 소속 | 패턴의 문법 |
  |---|---|---|---|
  | 폰 | 프롤로그 | 검은 말(어둠) | 한 칸씩 전진하며 압박, 앞 대각선 두 칸을 찍는 공격. 체력 50%에서 **승격** (몸이 커지고 퀸 패턴 일부 사용) |
  | 비숍 | 1장 (크레푸스) | 흰 말(빛) | 대각선 빔과 대각선 순간이동. 바닥의 흑백 칸에 따라 색과 공격이 바뀜 |
  | 잠식된 룩 | 4장 (디비시오) | **흰·검은 두 색이 섞인 말 (결정)** — 전쟁터인 디비시오에 맞춤. 처치 시 빛·어둠 반반 흡수 (지금 크레푸스 변이체 방식) | 직선 돌진, 성벽 소환 |
- **통일 장치**: 보스 자리 바닥을 **체스판 무늬**로, 모든 말은 같은 모델 문법(받침대 위에 말 머리 형태: 폰 둥근 머리, 비숍 갈라진 모자 등), 쓰러질 때 판 위에 **쓰러져 구르는** 연출
- 체스의 퀸·킹은 필드 보스로 쓰지 않는다 (두 왕·왕비와 겹침). 11번 항목에서 사용.
- 패턴이 단순하다는 문제는 체스 이동 규칙을 패턴의 문법으로 써서 보스마다 규칙이 다르게 함으로써 해결
- 영향 범위(예상): `MutantActor` 교체 또는 개편, `Bosses`(배치 표), 모델, `Arena` 바닥

### 10. 이명 체계와 스테이터스 창
- **스테이터스 창 신설**: 이름, 이명 목록, 빛·어둠 누적치, 균형도, 강화 단계를 볼 수 있는 창 (**키: Tab (결정)**)
- 이명 체계는 **2.1** 참고 (시작 이명 "신에게 선택받은 자", 인정 시 각 왕의 이명 추가, 영향 이탈 시 "판을 벗어난 자"로 교체)
- **이명의 실제 효과 (결정)**: 판을 벗어난 자 = 침식 허용치 제한 해제. 나머지는 표시만 (2.1)
- 영향 범위(예상): `Progress`/`Story.h`, 신규 UI 화면, `Hud` 또는 메뉴, `PlayerStatus`(침식 판정)

### 11. 킹·퀸 보스전 (진엔딩 경로에서 필수)
- **발동 조건**: 신의 영향에서 벗어난 뒤(이명 교체 후) 각 수도의 왕과 왕비를 다시 찾아가면, **신이 개입해서 왕은 킹, 왕비는 퀸으로 변모**한다.
- **횟수**: 나라마다 1회 (빛의 킹·퀸, 어둠의 킹·퀸, 총 2번)
- **인정 때의 결투는 지금과 동일** (왕과 일대일, 폼 고정). 킹·퀸전은 영향 이탈 뒤 다시 찾아갔을 때의 새 보스전. **(결정)** 15번 표의 "루키우스(킹)"·"녹티스(킹)"의 속성 보호막은 이 듀오전 안의 킹 기믹이다 (킹 단독전은 없음)
- **듀오전 설계 (초안)** — 상세 패턴은 E단계 계획 때 [ ]
  - **퀸**: 빠르고 넓게 움직이며 직선·대각선으로 압박
  - **킹**: 느리지만 맞으면 아픈 범위 공격, 체크처럼 칸을 막아 플레이어를 몰아세움. 나라에 맞는 속성 보호막(빛의 킹 = 빛 보호막, 어둠의 킹 = 어둠 보호막)
  - **퀸을 먼저 쓰러뜨리면** 킹을 지키던 방벽이 사라져 약점이 열림. 마지막에 킹이 쓰러지면 **체크메이트 연출**
  - 폼은 고정하지 않고 **자유** — 속성 보호막을 깨려면 폼을 바꿔야 하므로 (정리)
- **전투 후**: 왕과 왕비는 **죽지 않고 쓰러진다.** 말을 걸면 오류 텍스트만 반복 (신의 영향에서 벗어나지 못한 채로). 기존 영향 아래 NPC의 오류 연출 재사용.
- 조건 미충족자는 이 전투를 겪지 않는다.
- **체크메이트 엔딩 (결정, 신규)**: A·B를 갖췄지만 두 나라의 킹·퀸을 다 깨지 않고 키네라에 가면
  - 키니스는 대화 없이 바로 전투 (영향에서 벗어난 상대이므로 지금 진엔딩 조건 충족 시와 같음)
  - 처치 후 유언(세계의 진실)까지 듣고, **마지막 선택 전에** 킹·퀸이 나타나 주인공을 둘러싸고 죽임 → 체크메이트 엔딩
  - 한 나라만 깼다면 **남은 나라의 킹·퀸만** 나타남 (무엇을 놓쳤는지 보여 줌)
  - 전투가 아닌 연출로 처리 (17번 컷신 시스템 사용)
- 영향 범위(예상): `KingActor`/`LuciusActor`/`NoctisActor` 확장 또는 새 보스 클래스, `BossActor`, `Bosses`, `Dialogue`, `StoryEvents`, `EndingScreen`, `SaveGame`(본 결말 기록)

### 12. 수도 확장, 성 내부, 왕비

### 14. 잿빛 폼 개편 (낫 콤보 액션)

### 15. 보스 난이도 상향과 보스별 기믹
플레이어가 두 폼·필살기·콤보를 갖추면 지금의 보스는 쉬워지므로 보스를 함께 강화한다. 원칙은 **판독 가능한 어려움**(전조가 보이고 피할 수 있음).
- **3축**
  1. **페이즈 구조**: HP 구간마다 패턴 추가·변화 (체스에서는 "수가 바뀐다"는 연출)
  2. **조합 패턴**: 장판 + 투사체 + 돌진이 겹치는 연계. 회피(우클릭)와 폼 스왑 타이밍을 요구
  3. **기믹으로 폼 사용 강제**: 한 폼만 쓰면 못 깨게 해서 **빛·어둠 두 폼**을 오갈 이유를 만듦 (결정: 잿빛은 수락 후에만 있으므로 신 전투 외 기믹에는 잿빛을 쓰지 않음)
- **보스별 기믹 (초안, 보스당 핵심 기믹 1개)**
  | 보스 | 기믹 |
  |---|---|
  | 폰 | 무리로 등장, 끝 칸까지 전진하면 승격. 승격 전에 처치 |
  | 비숍 | 대각선 레이저, 안전 칸이 대각선 격자로 정해짐 (위치 선택이 핵심) |
  | 잠식된 룩 | 직선 돌진과 벽 파괴. 기둥을 이용해 돌진을 유도해 기절시킴 |
  | 빛의 킹 (듀오전) | 빛 속성 보호막, **어둠폼**으로만 깨짐 |
  | 어둠의 킹 (듀오전) | 어둠 속성 보호막, **빛폼**으로만 깨짐 |
  | 킹·퀸 듀오 | 한쪽이 보호막을 걸어 주면 다른 쪽을 먼저 쓰러뜨림 (11번 퀸 선격파 방벽과 통합) |
  | 루키우스·녹티스 (인정 결투) | **결투용 다른 기믹 (결정)** — 속성 보호막 대신 고정된 폼으로 풀 수 있는 기믹. 내용은 계획 때 제안 [ ] |
  | 신 | 판 전체가 기믹. 칸이 사라지거나 색이 바뀌어 안전 칸이 변함 (6번 결계 구조와 통합, 잿빛폼 하나로 공략) |
- **주의**: 기믹이 있는 보스는 분노(광폭화) 타이머를 길게 잡는 등 조정. 각 보스 상세 수치 [ ]
- 9번(필드 보스)·11번(킹·퀸)과 같은 단계에서 설계. 패턴 수치는 `Tuning.h`
- 영향 범위(예상): `BossActor` 및 각 보스 클래스, `Combat`, `Arena`

### 16. 보스 지역 설계 규칙
오픈월드에서 **보스 근처는 한눈에 보스전 장소임을 알 수 있게** 일반 필드와 배치를 다르게 한다. 3번(오픈월드)에 설계 규칙으로 포함한다.
- **접근 단계**
  - **원경 신호**: 멀리서도 보이는 거대 구조물(체스말 실루엣, 탑, 부서진 기둥), 하늘·안개 색 변화
  - **진입로**: 길이 정돈되고 폭이 좁아지며, 양옆에 체스판 무늬 바닥과 말 조각상
  - **경계 문턱**: 문·기둥 한 쌍·낮은 계단 같은 명확한 문턱, 지나면 BGM 변경
  - **전장(아레나)**: 원형/사각의 열린 공간, 가장자리는 벽·절벽·잿빛 안개로 막음
- **일반 필드와의 차이**: 장애물을 **대칭·규칙적(체스판 격자)** 으로 배치, 문턱 앞은 잡몹이 없는 고요 구간, 흑백 타일 바닥(아이소 뷰에서 가장 확실한 구분), 중앙만 밝은 조명(`SetGlow`, 림라이트)
- **아레나 원칙**: 보스 기믹에 맞춘 전용 배치(룩=기둥, 비숍=대각선 격자, 킹·퀸=보호막 기둥), 엄폐물은 위치 고정 또는 파괴 가능, 낙사·함정은 최소화(아이소 시점에서 판독이 어려움), 전투 중 이탈 불가(입구 봉쇄), 사망 시 재도전은 문턱 앞
- **보스별 분위기 (예시)**: 폰=체스판 들판과 낮은 조각상, 비숍=대각선 회랑과 기울어진 기둥, 룩=무너진 성벽 폐허와 돌진 파괴 흔적, 킹·퀸=수도 근처 왕실 정원 (12번과 함께 설계)
- 아레나 레이아웃은 15번 기믹과 함께 정함. 오브젝트 개수·타일 패턴은 `Tuning.h` 상수와 기존 렌더러 범위에서
- 참고: 지금은 보스 자리 반경 7타일의 지형지물을 비우는 처리(`Bosses::Arena`, `Props::SetArena`)가 있음 — 아레나 설계 때 이를 바탕으로 확장

### 17. 공통 컷신 시스템과 엔딩 컷신
- 엔딩을 텍스트 한 줄로 끝내지 않고 **컷신처럼 장면 장면을 보여 준다.**
- **방식**: 인게임 컷신. 실제 맵과 모델을 쓰고 카메라를 고정·이동시키며 캐릭터를 배치. 레터박스(위아래 검은 띠), 포스트프로세스(블룸·림라이트)와 글로우를 활용. **이미지 에셋이 필요 없고 외부 라이브러리도 쓰지 않는다.** 정지 컷만 합성하는 방식은 표현력이 낮아 쓰지 않는다.
- **카메라 줌 (결정)**: 추가한다. 지금 렌더러는 화면 1픽셀 = 월드 1픽셀이므로 월드 그리기에 확대 배율을 넣는다 (HUD·UI는 그대로). 화면 밖 판정, 마우스 → 월드 변환, 안개 거리, 블룸 버퍼가 배율을 따르도록 함께 고침 → A2 단계 작업이 커짐
- **공통 컷신 시스템**(카메라 스크립트, 컷 단위 재생, 레터박스, 페이드·화이트아웃, 자막/대사, 시간 제어)을 **먼저 만든다.** 13번 필살기 컷인, 4번 신의 개입 연출, 이명 획득 연출, 11번 체크메이트 연출, 엔딩이 모두 재사용한다.
- **컷 구성 틀**: 엔딩당 5~8컷, 컷마다 카메라 위치·등장 모델·조명 색·짧은 대사·길이(3~6초) 지정. 마지막에 엔딩 이름과 이명, 플레이 기록(선택·이명)을 표시. 스킵은 길게 누르기, 재플레이는 빠른 넘기기. 컷 데이터는 `Tuning.h`/코드 안 표에 둠 (데이터 파일·파서 금지)
- **엔딩별 연출 방향 (예시)**
  | 엔딩 | 방향 |
  |---|---|
  | 구원자 | 밝은 하늘로 흐르는 카메라, 마을이 복구되는 짧은 장면 모음 |
  | 잿빛 | 색이 서서히 빠지며 고요해지는 세계, 홀로 선 주인공 실루엣 |
  | 버려진 말 (옛 신의 계략) | 체스판을 내려다보며 신의 손이 말을 정리하는 장면 |
  | 체크메이트 (신규) | 킹·퀸이 사방을 막아 서고, 판 위에서 주인공의 말이 쓰러짐 |
  | 진엔딩(판을 벗어난 자) | 체스판 경계선을 걸어 판 밖으로 나가고, 판이 작아지며 끝남 |
- 엔딩별 컷 목록과 대사 [ ] — F단계에서 Claude 초안 → 검토
- 영향 범위(예상): 신규 `Cutscene` 계열, `Camera`, `Renderer`(줌 배율), `PostProcess`, `StoryEvents`, `Hud`

### 18. 모니터링 시스템 (오픈월드 전환 뒤)
게임 상태를 로컬 PC의 브라우저(HTML)에서 실시간으로 확인한다. **오픈월드 전환(3번, D단계)이 끝난 뒤에 한 번에 만든다 (결정)** — 지금은 들어가 있는 지역 하나만 메모리에 만들어져서, 마을별 실시간 상태는 오픈월드가 되어야 의미가 있기 때문.

**필수 항목**
- 각 NPC 상태: 종류, 소속 양식, 위치, 지금 하는 대사, 대화 중인지, 신의 영향 아래인지(오류 반응을 하는지). 지금 NPC에는 체력 같은 상태 값이 없으므로 이 구성으로 시작 [ ] (오픈월드·퀘스트 이후 NPC에 상태가 늘면 함께 추가)
- 각 마을별 전체 상태: 이름, 양식, 신전, NPC 수, 그 마을 주변 몬스터 수, 가 본 곳인지 (세부 항목은 7번 마을·퀘스트 구조에 맞춰 계획 때 확정 [ ])
- 몬스터 수 (종류·소속별 포함), NPC 수

**방식 (결정)**
- **게임 안 로컬 서버 + SSE(Server-Sent Events)**: 게임이 HTML 화면과 JSON 메시지를 직접 보낸다. 브라우저에서 `http://127.0.0.1:포트`를 열기만 하면 됨. 게임 → HTML 한 방향
  - Windows 기본 Winsock(`ws2_32`) 사용 — 외부 라이브러리 아님
  - `127.0.0.1`에만 열어 다른 PC에서는 접속 불가
  - 스레드 없이 매 프레임 잠깐 확인하는 비차단 방식 (게임 상태를 안전하게 읽음)
  - HTML은 받은 JSON으로 화면을 갱신하고, 게임이 꺼졌다 켜지면 다시 연결
- JSON은 작은 작성기를 직접 만들어 씀 (라이브러리 없음)
- 켜고 끄기는 디버그 키(F4 [제안]), 기본은 꺼짐 [제안]. 포트·보내는 주기(0.5초 [제안])는 `Tuning.h`

**JSON 메시지 (초안)**

## 4. 진행 순서 (권장)
각 단계는 "계획 → 확인 → 구현 → 사용자 빌드·실행 확인 → 문서 갱신" 순서.

| 단계 | 항목 | 이유 |
|---|---|---|
| A | 1, 2, 10 | 문서 정리와 이명·스테이터스 창. 소규모이고 이후 작업의 기반 — **구현함 (2026-10-12, 빌드 확인 대기)** |
| A2 | 17의 **공통 컷신 시스템 부분만** (카메라 줌 포함) | 4번 신의 개입, 13번 필살기 컷인, 11번 체크메이트, 엔딩이 모두 재사용하므로 먼저 — **구현함 (2026-10-13, 빌드 확인 대기)** |
| B | 4, 6 + 14, 5 | 신·엔딩 쪽과 잿빛 폼 개편. 6과 14는 같이 계획(잿빛폼이 유일한 폼이 되므로). 6 → 5 순서 |
| B2 | 13 | 폼이 정리된 뒤 폼별 필살기와 컷인 |
| C | 9 + 15(필드 보스 부분) | 필드 보스 교체와 기믹. 보스 배치는 지역 개편 후에도 유지됨 |
| D | **3 + 7 + 8 + 12 + 16의 통합 계획**, 이후 구현 순서: 3 → 12 → 7 → 8 (16은 3·12·C 보스 아레나에 맞춰 적용) | 모두 지도와 마을 구조에 걸려 있음. 먼저 하나의 계획으로 설계 |
| E | 11 + 15(킹·퀸·신 기믹, 결투 기믹) + 체크메이트 엔딩 | 12(왕비·알현실)와 B단계(이명 교체)가 끝난 뒤 가능 |
| D2 | 18 모니터링 | 오픈월드 전환 직후. 마을별 실시간 상태가 가능해진 뒤 |
| F | 17의 엔딩 컷신 (5종) | 엔딩 조건과 장면이 모두 확정되고 컷신 시스템이 완성된 뒤 마지막에 |

## 5. 결정 사항과 남은 것

### 5.1 결정 사항 (2026-10-12)
| 항목 | 결정 |
|---|---|
| 잿빛폼 보유 시점 (6·15) | 수락 후에만, 잿빛폼 하나만 남음. 세 폼 공존 없음 → 보스 기믹은 빛·어둠 두 폼 기준 |
| 킹·퀸전과 왕 결투 (11·15) | 첫 만남 = 인정 결투(지금 그대로). 영향 이탈 후 재방문 = 킹·퀸 듀오전. 킹의 속성 보호막은 듀오전 안의 기믹. 듀오전은 폼 자유 |
| 영향 이탈 조건 (2.3) | 지금 그대로: 두 왕 추궁 + 구원 두 번 + 엿듣기 + 누적치 합 400 |
| 진엔딩 경로 (2.3) | A + B + 두 나라 킹·퀸 격파 → 키니스 → 마지막 선택 → 신 |
| 체크메이트 엔딩 (신규) | A·B 충족, 킹·퀸 미격파 → 키니스(대화 없이 전투) → 유언 뒤, 선택 전에 깨지 않은 나라의 킹·퀸이 나타나 주인공을 죽임 |
| 엔딩 이름 | "신의 계략 엔딩" → **버려진 말** |
| 플래그 정리 (2.3, 기본안) | `TitleChosenByGod`를 지우고 `EscapedGodInfluence`로 합침. 킹·퀸 격파는 나라별 새 플래그 |
| 이명 효과 (10) | 판을 벗어난 자 = 침식 허용치 제한 해제. 나머지는 표시만 |
| 스테이터스 창 키 (10) | Tab |
| 잿빛폼 입력 (6·14) | 좌클릭 = 4단 낫 콤보, 우클릭 = 대시 베기, E 풀어내기, Q 소거, Space = 새 기술 |
| 잿빛폼 위력 (6) | 누적치와 무관한 고정값 |
| 지금의 파문 (14) | 없앰 (탄 지우기는 Q 소거에만) |
| 필살기 (13) | 별도 게이지(때리거나 맞으면 충전), R 키, 컷인 중 완전 정지, 보스에게는 최대 체력의 일정 비율까지만, 신 전투에서도 같은 제한으로 사용 가능 |
| 잠식된 룩 소속 (9) | 흰·검은 두 색이 섞임, 처치 시 빛·어둠 반반 흡수 |
| 인정 결투 기믹 (15) | 속성 보호막 대신 결투용 다른 기믹 추가 |
| 몬스터 재생성 (3) | 신전에서 쉴 때(월드 전체) + 지역을 멀리 벗어났다 돌아올 때(그 지역만) |
| 퀘스트 보상 표기 (7) | 공개 |
| 왕비 이름 (12) | 솔레나(빛) / 녹타(어둠) |
| 컷신 카메라 (17) | 줌 추가 |
| 모니터링 (18) | 게임 안 로컬 서버 + SSE, 오픈월드 전환 뒤 한 번에 구현 |
